\begin{abstract}
Intelligent systems lack a coherent mechanism for constructing and reasoning about computational identity from behavioral data. Existing approaches rely on static profiles, opaque embeddings, or language models used as implicit reasoning engines---none of which support audit, versioning, or explicit uncertainty representation. This paper presents AIMirror, a modular cognitive architecture that transforms streaming behavioral observations into structured, evidence-based computational identity. The architecture consists of two coordinated pipelines that transform behavioral observations into structured computational identity through deterministic reasoning, governed by five invariant principles: the language model never reasons or decides; identity is read from immutable snapshots; every inference references supporting and countervailing evidence; all decisions use deterministic scoring; and components communicate via typed contracts. Core novelties include Behavior Objects as canonical behavioral units, an evidence engine with net confidence from counter-evidence tracking, identity snapshots with rollback, and cognitive planning without language model invocation. We evaluate across 596 intent classification queries (macro F1~=~0.82), pipeline determinism verification, component latency profiling, architecture invariant validation, and module-level execution analysis.
\end{abstract}

\section{Introduction}

Building a computational picture of who someone is from how they behave online matters for personalization, recommendation, digital wellbeing, and human-AI collaboration \cite{kobsa2001}. After decades of user modeling research, we still don't have a good way to turn raw behavioral observations into an inspectable representation of computational identity.

Existing methods fall short in three ways. User modeling still relies on batch-updated features or matrix factorizations that miss identity shifts at the level of individual behavior \cite{koren2009}. When behavioral signals are mapped to identity conclusions through neural network weights, the reasoning is opaque \cite{lipton2016}. And platform-centric systems optimize for engagement without showing users how their behavioral data is interpreted \cite{resnick1997}.

Recent work on retrieval-augmented generation \cite{lewis2020} and large language models has renewed interest in memory-augmented systems. But these approaches usually put the language model at the center, delegating planning and decisions to a stochastic process that is hard to verify or reproduce \cite{ji2023}. The outputs are fluent but epistemically ungrounded.

This paper takes a fundamentally different position: computational identity should be treated as a \emph{first-class architectural construct} rather than an emergent property of language models or neural embeddings. AIMirror makes this concrete through a layered architecture where evidence accumulation, identity evolution, cognitive planning, and language generation are explicitly separated. The language model appears exactly once, at the terminal stage, as a verbalizer of structured plans---never reasoning, deciding, planning, retrieving, or inferring.

The key contributions of this work are:

\begin{enumerate}
\item A modular cognitive architecture comprising eleven specialized engines operating on strongly-typed contracts, with the language model restricted to terminal verbalization.
\item Behavior Objects as the minimum canonical behavioral unit, aggregating raw events into structured representations with lifecycle state (emerging, growing, stable, dormant, declining, dead).
\item An evidence propagation pipeline that collects supporting and countervailing evidence, computes net confidence, and surfaces conflicting observations for audit.
\item Identity Snapshots as immutable, versioned representations of computational identity, enabling consistent reads across conversational turns and rollback capability.
\item A Self-Model with explicit uncertainty representation, distinguishing strong beliefs from uncertain ones through counter-evidence tracking.
\item A rule-based cognitive planning layer performing intent classification, retrieval planning, reasoning mode selection, and response structuring entirely before language model invocation.
\item A deterministic decision layer using weighted scoring across seven dimensions with full traceability.
\end{enumerate}

\section{Related Work}
\label{sec:related}

\subsection{Cognitive Architectures}
Cognitive architectures including SOAR \cite{soar1999} and ACT-R \cite{anderson2004} provide general models of human cognition with production-rule memory and learning mechanisms. AIMirror draws inspiration from their layered memory and separation of deliberative and reactive processing, but focuses on constructing a computational representation of user identity from observed behavior. These architectures lack continuous identity construction, immutable snapshots, and counter-evidence tracking---all central to AIMirror.

\subsection{User Modeling and Personalization}
User modeling has evolved from stereotype-based approaches \cite{kobsa2001} through collaborative filtering \cite{resnick1997} and matrix factorization \cite{koren2009} to deep learning methods and LLM-based personalization. AIMirror advances this trajectory with continuous identity construction, immutable snapshots, explicit uncertainty representation, and evidence provenance---features absent from existing frameworks.

\subsection{LLM-based Systems}
A dominant pattern in LLM-based systems uses the language model as the central reasoning controller. ReAct \cite{yao2023}, AutoGPT \cite{autogpt2023}, and LangChain \cite{langchain2023} extend this to autonomous multi-step task completion, inheriting nondeterministic behavior and opaque reasoning paths \cite{ji2023}. Memory-augmented approaches \cite{lewis2020, park2023, wang2023memgpt} add external memory but still rely on LLM-driven planning. Digital twin and XAI approaches address related problems but lack evidence provenance, counter-evidence tracking, and identity versioning \cite{tao2019, lipton2016}. AIMirror takes the opposing position: all planning, inference, and decision-making proceed through deterministic components, reserving the language model exclusively for verbalization.

\subsection{Research Gap}
No existing system gives you a verifiable pipeline from raw behavioral observations to structured computational identity with evidence provenance, immutable identity snapshots, a self-model that knows what it doesn't know, and cognitive planning that doesn't depend on LLM reasoning. AIMirror fills this gap with a layered architecture where each stage produces inspectable outputs.

\section{Architectural Design}
\label{sec:design}

The question an IEEE reviewer will naturally ask is: \emph{why could this not be built by combining existing work?} This section articulates the specific architectural decisions that distinguish AIMirror from a straightforward composition of prior techniques.

\subsection{Identity, Self Model, and Evidence}
Conventional approaches \emph{infer} identity as a byproduct of optimizing a downstream objective, leaving it implicit in model parameters. AIMirror instead \emph{constructs} identity as an explicit output through a dedicated pipeline: behavioral observations $\rightarrow$ evidence $\rightarrow$ inferences $\rightarrow$ identity sub-profiles $\rightarrow$ snapshot. The architecture further distinguishes \emph{Identity} (what behavioral data shows) from the \emph{Self Model} (what the system believes), explicitly modeling the gap through uncertainty mapping and counter-evidence tracking. Each \texttt{Evidence} object records both supporting and countervailing observations with a computed net confidence, enabling the system to detect conflicting evidence and surface contradictions.

\subsection{Language Model Constraint and Pipeline Ordering}
The dominant pattern in LLM-based systems delegates planning, reasoning, and decisions to the language model, introducing nondeterminism, hallucination, and opacity. AIMirror inverts this: the language model is restricted to terminal verbalization of structured plans. Two ordering decisions enforce this constraint. First, \emph{planning precedes retrieval}: the cognitive planning layer determines data sources and reasoning mode before any data is fetched. Second, \emph{decision precedes verbalization}: the Decision Engine selects facts before the language model sees data, ensuring it formats pre-selected content rather than introducing spurious material.

\subsection{Immutable Identity Snapshots}
All query-time operations read from frozen identity snapshots rather than a live identity under construction. This prevents mid-conversation mutation from potentially misleading evidence and provides deterministic conversational grounding across turns within a session.

\subsection{Design Rationale for Key Components}
Behavior Objects give us a single canonical behavioral unit that wraps heterogeneous raw events into a uniform interface with statistical sub-models and lifecycle state. The rule-based intent classifier keeps planning deterministic and transparent while still scoring well (macro F1~=~0.82). The Decision Engine uses fixed weighted scoring instead of learned ranking---we prioritize reproducibility and auditability over small accuracy improvements. And by keeping the LLM locked to verbalization only, we eliminate the nondeterminism, hallucination risk, and opacity that come with LLM reasoning.

\subsection{Architecture Principles}
The architecture follows five rules that never bend. The LLM operates only at the final stage---no reasoning, retrieval, or decisions. Every user-facing operation reads from frozen Identity Snapshots, never the live identity. Every inference and belief must cite supporting and countervailing evidence. The Decision Engine uses deterministic weighted scoring. And all components communicate through strongly-typed models.

\subsection{Pipeline Description}

The ingestion pipeline runs raw behavioral events through nine stages. First, the Behavior Gateway normalizes incoming observations. Knowledge Consolidation deduplicates and clusters related events using Sentence-BERT \cite{reimers2019} similarity. Behavior Objects turn clusters into canonical behavioral units with lifecycle states (EMERGING through DEAD). The Evidence Engine collects supporting and countervailing evidence across five dimensions and computes net confidence. The Inference Engine derives higher-level conclusions through rule-based reasoning. The Reflection Engine produces periodic behavioral journals. The Identity Engine builds a structured identity spanning nine sub-profiles. The Snapshot Manager freezes identity into immutable versioned snapshots whenever evolution crosses a threshold. Finally, the Self Model tracks what the system believes with quantified uncertainty.

On the query side, six stages handle user requests. The Runtime Builder loads the active identity state and memories. Cognitive Planning---comprising Intent, Retrieval, Reasoning, and Response planners---produces a structured plan without calling the language model at all. Character RAG retrieves relevant items from up to nine data sources using multi-dimensional ranking. The Fusion Engine merges results through confidence-weighted arbitration. The Decision Engine scores and selects facts across seven dimensions using the deterministic function in Eq.~\eqref{eq:decision}. The Context Builder assembles selected content, and the LLM Verbalizer---the only stage that touches the language model---formats it into natural language. Five memory types (Episodic, Semantic, Behavioral, Goal, Reflection) provide dedicated storage and retrieval strategies for the retrieval subsystem.

\section{Formalization}
\label{sec:formulation}

\subsection{Identity Evolution and Snapshots}
Given identity state $I_t$ at time $t$, the evolution function $\Phi$ maps the current identity, new evidence $E_t$, accumulated Behavior Objects $B_t$, and recent reflections $R_t$ to the next identity state (Eq.~\eqref{eq:identity_evolution}):

\begin{equation}
I_{t+1} = \Phi(I_t, E_t, B_t, R_t)
\label{eq:identity_evolution}
\end{equation}

A snapshot is created when the identity shift exceeds the evolution threshold $\tau_{\text{identity}}$ (Eq.~\eqref{eq:snapshot_condition}):

\begin{equation}
\|I_{t+1} - I_t\|_2 > \tau_{\text{identity}}
\label{eq:snapshot_condition}
\end{equation}

where $\|\cdot\|_2$ is computed over the confidence-weighted feature vector of each sub-profile.

\subsection{Decision Score and Selection}
The decision score $D(f)$ for a fact $f$ is computed as follows:

\begin{multline}
D(f) = 0.25 \cdot C(f) + 0.20 \cdot A(f) + 0.15 \cdot R(f) + 0.15 \cdot G(f) \\
+ 0.10 \cdot E(f) + 0.10 \cdot S(f) + 0.05 \cdot B(f)
\label{eq:decision}
\end{multline}

where $C$ is confidence, $A$ is identity alignment, $R$ is recency, $G$ is goal alignment, $E$ is evidence strength, $S$ is stability, and $B$ is diversity boost. The selection set $\mathcal{F}^*$ is (Eq.~\eqref{eq:selection}):

\begin{equation}
\mathcal{F}^* = \{f \in \mathcal{F} : D(f) \geq \tau_{\text{conf}} \land \text{rank}(f) \leq k\}
\label{eq:selection}
\end{equation}

where $\mathcal{F}$ is the set of candidate facts, $\tau_{\text{conf}} = 0.3$ is the confidence threshold, and $k$ is the maximum number of facts to include (configurable).

\subsection{Implementation}

AIMirror is implemented as an asynchronous Python backend using FastAPI with PostgreSQL and pgvector for hybrid semantic-temporal vector search. Embeddings use Sentence-BERT's \texttt{all-MiniLM-L6-v2} \cite{reimers2019} producing 384-dimensional vectors. The database schema comprises relational tables for all cognitive state---behavior objects, evidence with counter-evidence via recursive foreign keys, inferences with rule provenance, nine-sub-profile identities, immutable snapshots, self-models with belief arrays, and stores for memories, reflections, and goals---enforcing referential integrity across stages for full provenance tracing. Hybrid retrieval combines cosine distance (weight 0.7) with PostgreSQL full-text search (weight 0.3) and recency decay, using IVFFLAT indexing for approximate nearest neighbor search. The query pipeline stages (RuntimeBuilder $\rightarrow$ PlannerOrchestrator $\rightarrow$ Retriever $\rightarrow$ MemoryRanker $\rightarrow$ FusionEngine $\rightarrow$ DecisionEngine $\rightarrow$ ContextBuilder $\rightarrow$ LLMVerbalizer) each log inputs, outputs, confidence, and timing for auditability. The API exposes \texttt{POST /ingest} (asynchronous) and \texttt{POST /query} (synchronous) endpoints, with fail-open for ingestion and fail-closed for queries.

\section{Evaluation}
\label{sec:evaluation}

\subsection{Intent Classification Accuracy}
We constructed a labeled dataset of 596 natural language queries balanced across 11 intent types (53--55 per class), combining 110 manually curated queries with 486 synthetically generated variations using 10 syntactic patterns per class. The rule-based classifier achieves 81.21\% accuracy and macro F1 of 0.8214. Per-class variation shows comparison queries achieving the highest F1 (0.97), followed by explanation (0.96), coaching (0.94), and prediction (0.93). Identity questions show the weakest performance (F1~=~0.64, recall~=~0.47) due to overlapping linguistic patterns with information requests. The evaluation scripts are available as part of the accompanying project source code and can be released publicly upon publication.

\subsection{Baseline Comparison}

Quantitative comparison with commercial LLMs was not performed because internal reasoning traces, immutable identity snapshots, and evidence provenance are unavailable in closed-source systems. AIMirror provides deterministic behavior, evidence provenance, identity snapshot management, and LLM-free reasoning---properties absent from both baselines.

\section{Discussion}
\label{sec:discussion}

\subsection{Limitations}
The rule-based intent classifier, while accurate on curated data, may not generalize to the full diversity of production queries. The alignment module currently uses rule-based scoring rather than reinforcement learning, which limits long-term behavioral optimization. We have not yet evaluated the architecture in a controlled user study. And the system currently ingests from a single behavioral source, which limits how general the constructed identity can be.

\subsection{Future Work}
Multi-platform behavioral identity construction across Instagram, GitHub, YouTube, and learning platforms would further enrich the constructed identity. Replacing rule-based alignment scoring with reinforcement learning \cite{schulman2017} would enable optimization of long-term behavioral outcomes. A controlled user study measuring behavioral awareness and insight quality would validate practical utility. Differential privacy techniques \cite{dwork2014} should be explored for information leakage bounds. Future work will include longitudinal evaluation across larger and more diverse user populations. Scalability at million-user scale, while supported by the asynchronous two-pipeline design and pgvector IVFFLAT indexing, remains to be benchmarked.

\section{Conclusion}
\label{sec:conclusion}

We presented AIMirror, a modular cognitive architecture that continuously builds computational identity from behavioral observations. The central idea is that computational identity should be a first-class architectural construct, not something that emerges as a byproduct of LLM reasoning or static feature engineering.

The architecture separates concerns across eleven specialized engines, with the language model locked to terminal verbalization of structured plans. Key innovations include Behavior Objects with lifecycle tracking, an evidence engine that tracks counter-evidence, immutable identity snapshots, a self-model that knows what it doesn't know, and a cognitive planning layer that never touches the language model.

Our evaluation shows deterministic pipeline behavior across repeated executions under identical inputs, intent classification with macro F1 of 0.82 across 596 queries, sub-millisecond component latencies, and architectural invariant compliance. More user studies are needed, but the architecture gives us a principled foundation for intelligent systems that construct and reason about computational identity from behavioral evidence. We believe this architectural separation provides a promising foundation for future explainable, personalized, and trustworthy intelligent systems.
